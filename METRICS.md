# CT Code Metrics

This repo ships two complementary measurement systems that answer two questions every project team cares about:

1. **How much of this codebase is still template code vs. product-specific work?**
2. **How much of the code was written by AI vs. humans?**

Both metrics are computed automatically on every merge to `main` and posted to the shared Grafana dashboard via DevLake.

---

## 1. Template vs. Custom Metrics

### What it measures

Compares the current state of the repo against the baseline commit recorded in [`.template-provenance.json`](.template-provenance.json) to determine how much of the code has diverged from the original Code & Theory React Native template.

| Metric | Meaning |
|---|---|
| `template_pct` | % of lines that are still identical to the template |
| `custom_pct` | % of lines that have been added or changed by the team |
| `total_loc` | Total lines of code in the repo at the time of measurement |

### How it works

- The `baseline_commit` field in `.template-provenance.json` pins the exact commit that represents the pristine template state.
- At CI time, `template-metrics.mjs` diffs the current HEAD against that baseline across all tracked source files.
- Lines unchanged from the template count as **template**; every line added, removed, or replaced counts as **custom**.
- An optional `ANTHROPIC_API_KEY` secret enables Claude-powered semantic scoring: cosmetic reformatting is excluded so whitespace-only diffs don't artificially inflate the custom percentage.

### When it runs

Triggered by the [`CT Code Metrics`](.github/workflows/template-metrics.yml) GitHub Actions workflow on:
- Every push to `main`
- Every merged pull request
- Manual `workflow_dispatch`

## 2. AI Attribution Metrics

### What it measures

Tracks how much of the committed code was generated by an AI assistant (Claude Code or Cursor) vs. typed by a human developer.

| Metric | Meaning |
|---|---|
| `ai_pct` | % of committed lines that came from an AI tool |
| `human_pct` | % of committed lines written by a developer |
| `commits_with_attribution` | Number of commits that carry AI attribution data |
| `commits_analyzed` | Total commits examined |
| `coverage_pct` | What fraction of commits have attribution data |

### How it works — two-step local instrumentation

**Step 1 — Snapshot (at write time)**

Every time Claude writes or edits a file, the `snapshot_ai_output.py` hook fires immediately after the tool call completes. It saves the exact content Claude produced into `.claude/ai_snapshots/`. This snapshot records the AI's "raw output" before any developer edits.

**Step 2 — Attribution (at commit time)**

When the developer runs `git commit`, the `compute_attribution.py` hook (wired as a `prepare-commit-msg` git hook) compares each staged file against its snapshot:

- Lines that are **identical to the snapshot** → counted as **AI lines** (the developer kept the AI output as-is).
- Lines that are **different or new** → counted as **human lines** (the developer modified or added them).

The hook appends a summary block to the commit message:

```
─────────────────────────────────────────
🤖 AI Attribution Summary (Claude Code)
─────────────────────────────────────────
  Overall  →  AI: 72%  |  Human: 28%
  Generated: 2026-07-01 10:30 UTC

  Per-file breakdown:
    src/screens/HomeScreen.tsx
      [███████░░░]  AI 72% (144 lines)  /  Human 28% (56 lines)
─────────────────────────────────────────
```

At CI time, `ai-attribution-metrics.mjs` reads this data from git history across all commits and aggregates it into repo-level percentages.

> Files with no snapshot (i.e., files the developer wrote from scratch without AI help) are counted as 100% human.

---

## 3. Combined Dashboard Payload

After both scripts run, the workflow merges the results into a single JSON payload and POSTs it to DevLake. The Grafana dashboard then surfaces all four numbers together:

```
metrics: 34% template / 66% custom | 58% AI / 42% human
```

## Setup

### Prerequisites

Add these secrets to your GitHub repository (`Settings → Secrets and variables → Actions`):

| Secret | Purpose |
|---|---|
| `CT_METRICS_TOKEN` | GitHub PAT with read access to `codeandtheory/ct-github-code-metrics` |
| `DEVLAKE_WEBHOOK_URL` | Webhook URL from your DevLake admin |
| `DEVLAKE_BASIC_AUTH` | `user:pass` for the DevLake config UI |
| `ANTHROPIC_API_KEY` | *(Optional)* Enables semantic template scoring |

### Install local AI attribution hooks

Run `/setup-ct-metrics` or `/integrate-ai-tracker` inside Claude Code (or the equivalent Cursor command) to wire up the local git hook. Once installed, every commit you make will automatically carry AI attribution data — no further action needed.

### Verify the baseline

Open [`.template-provenance.json`](.template-provenance.json) and confirm `baseline_commit` points to the correct starting commit for this project. If you initialized the project from a fork or a manual copy, update this SHA to the first commit that represents the unmodified template state.
